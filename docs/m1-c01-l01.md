## 运行方法

要求 Node.js `>=20.19.0`、npm、Git 和具有 WebGL2 能力的桌面浏览器。初次准备需要从官方 GitHub 获取固定 ArkGlide 提交，并按两份 lockfile 安装依赖；后续复用有效缓存。

在仓库根目录执行：

```bash
npm ci
npm run dev
```

浏览器访问 `http://127.0.0.1:4173`。服务仅监听本机；远程机器需自行配置端口转发，本轮未验证云平台的外部预览功能。外层播放器开始后，点击游戏画面取得鼠标锁定；首次点击只取得控制，不操作机关。`WASD` 移动、鼠标观察、`E` 操作所指机关、空格跳跃、`Esc` 暂停/释放鼠标、`R` 从本关安全入口重试。重试撤销启用折口、梯闩和完成状态，再次点击恢复控制。默认端口可用 `PORT` 环境变量更改。

这是一条**独立灰盒测试入口**：玩家直接从 L01 下层 O1 开始，移动/观察/E 已可用；没有制作 S01，也没有通过初始逻辑伪造穿门或上层抵达。正常过关过程不改玩家坐标、不切换镜头；初生、R重试及跌出边界的安全恢复均使用入口，不推进谜题状态。

针对性语法检查与浏览器验证：

```bash
npm run check
npm run test:browser
```

浏览器测试默认使用 `/usr/bin/chromium`。其他安装位置可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定。测试环境必须有兼容 Chromium；测试脚本不把缺少浏览器当作通过。`test:browser` 自动准备本关导出、使用临时 HTTP 端口、以键鼠输入运行，并将证据写入 `docs/evidence/m1-l01/`。

输入方法须准确区分：键盘由 Playwright 发送；鼠标观察使用带 `movementX/movementY` 的合成相对 `PointerEvent`，经过原生 input、camera rig 的正常处理路径。这样避开 CDP 在 pointer lock 下重新居中抵消相对移动的限制。测试只读快照来决定下一次输入，不直接写相机旋转、玩家位置、物理状态或通关旗标；它仍是自动化输入，不能称为硬件鼠标体验测试或真人试玩。

暂停也分两层：游戏内退出 pointer lock 后只将模拟时标置0，原生 session 仍活动，菜单R可接收；外层播放器的暂停会停用 session，不能用它验证游戏内菜单R。Headless Chromium 的键盘 Escape 未能触发操作系统级解锁，测试以标准浏览器 `document.exitPointerLock()` 触发原生 `pointerlockchange`，再发送真实键盘R；**硬件Esc、焦点丢失与半穿门暂停仍需实际体验**。外层播放器暂停另行验证模拟冻结/恢复。

`npm run dev` / `test:browser` 调用 `prepare:game`，同步原生运行时并生成 `.generated/l01/`；不运行完整引擎编辑器构建，不制作 ZIP。缓存 `.cache/arkglide/` 和生成输出可重新准备，不作为游戏源码交付。

### Windows 启动维护（2026-10-17）

用户在 Windows / Node.js24.19.0 下报告引擎下载后出现 `spawn npm ENOENT`。旧脚本用 `spawn('npm', args)`，无法直接启动 Windows 的 `npm.cmd`。现优先用 `process.execPath` 执行 npm 提供的 `npm_execpath` CLI 文件，参数仍作为数组传递，不经过 shell。直接调用脚本且没有该环境变量时，Windows 尝试 Node 同目录的标准 npm CLI；若不存在则提示通过 `npm run dev` 或 `npm run setup:engine` 启动。

`npm run test:setup` 四项回归通过：模拟 Windows 分支的真实子进程参数传递（路径含空格、中文和 shell 特殊字符）、安装失败退出码/错误保留、CLI 缺失提示，以及本机 npm CLI 调用；`npm run prepare:game` 复用已有缓存也已通过。执行平台仍是 Linux，**未声称在真实 Windows 上完成启动验证**。未重跑与此修复无关的浏览器谜题测试；下文三项浏览器结果保留原交付时的证据。更新脚本后可保留已经下载的 `.cache`，无需删除引擎重新下载。

## 实现与原生能力边界

- 固定引擎为 `arkglide/arkglide@da8ea1cf098ad99ccc89451d34bf4e272cdc15aa`；[引擎准备脚本](../scripts/engine.mjs)验证 SHA 与受跟踪文件状态，使用上游 lockfile，拒绝悄悄换版本或使用被修改的引擎缓存。
- [场景描述](../game/project.mjs)只生成 L01 地坪、设备、梯段、门框、真实护板、交互物和浅出口门斗；正式美术与设施后续空间未制作。
- 当前场景为97个节点、63个原生物理体。两盏必要灰盒点光强度各为0.18；出口用无碰撞深色背板与浅色门冠形成对比，不添加空气墙或正式美术资产。
- [本关脚本](../game/l01.js)使用原生 character、first-person camera rig、`portals.addSurface/create/place/link/watch`、跨门 raycast、motion 和 saves。A1/B1 通过真实安装面和射线安装；穿越、碰撞、身体映射及画面由引擎处理。没有自写触发区传送、路线瞬移或播放式通关。
- 遮板实际收起到位才启用折口；梯闩操作后返回梯门与出口门上升，两者进度到位才标记返回路可用。E 按实际相机射线和 1.8m 总路径选目标，不能隔实体墙操作。
- 完成条件为：梯闩对应机构到位，真实胶囊处于上层出口门斗安全体积。不是看见出口、按下手柄、靠近出口的下层投影或命中特定作者路线触发器。
- R 使用原生初始快照恢复门对、物理和本关 provider 状态，清理输入并暂停等待再次点击。未实现跨会话正式章节存档，也未接入 M0 的完整剧情 provider。
- 当前反馈为可辨材质、机关运动、短提示及准星。完整广播、正式音效、W 卷闸、拿放/跨门抓取、自由放门和其他单元均不在本轮实现内。

从平台中间 `(22.6,2.4,10)` 直接回望，低处被1.3m实心护栏挡住。09路线以真实输入步行靠近西缘约 `(20.8,2.4,12.2)`，默认走位容差0.32m。更新后的图已实际复核：能看见 A1 柜体、手柄顶与同一设备上缘，**O1 起点地坪仍被中设备挡住**；瞄向 O1 眼高的空气不等于看见起点。图03另由 B1 原生窗口呈现低层视图，不是合成假景。能否据这些线索自然认出之前区域仍待初见玩家验证。
