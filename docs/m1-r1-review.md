## 授权、反馈与范围

用户已经亲自游玩 M1，确认能够正常通关，并指出“第一个开关启用固定传送门，通过后再操作第二个开关就结束”，缺少探索、角色陪伴、语音反馈和剧情氛围。这是一次真实用户反馈，**不等于体验合格验收**。用户明确批准本轮对L01进行体验重构，新增最小随行角色和离线语音/字幕系统。

本轮没有制作 S01、L02、L03、其他章节、自由放门或通用NPC寻路。未来角色成长是文档预留。几何、栈雀和活动部件都是功能灰盒，未完成正式美术、正式动画和综合体验验收。修改仍使用固定 ArkGlide 原生角色、相机、物理、折口、运动、音频和快照能力，未复制引擎源码。

## 本轮可玩内容

- 高处出口、低侧受阻楼梯、围绕设备的管槽形成初始观察与检修探索。
- 设备侧手轮改为按住E，遮板逐步抬升，松开保持；门必须等真实让开才原生启用。
- 可选检视百叶打开设备横向槽，展示同一设施的另一面，不构成新增必按按钮。
- 透空上层栏杆提供低庭回望；配重闩以可见机械反馈开放返回梯和出口。
- 原创栈雀肩侧挂载，有待机/观察/说话与近门收折；不参与碰撞、不移动玩家、不替玩家解题。
- 11句数据对白、单队列事件调度、字幕、V/B独立开关，及4个原创机械音效。

实现迭代中已修正手轮支撑挡住中心交互射线的问题；观察高出口增加真实遮挡检测；检视对白延后至百叶实际到位；机械音效异常由游戏层隔离，已结束句柄不再参与暂停/恢复调用。原生静态包音频惰性载入曾使机械音效没有实际buffer，准备脚本现用原生 `build.preload` 的 `audio:ID` 预载四个文件。栈雀部件同比缩至0.82，减轻占屏；实际看图发现近栏穿模后，又加入原生射线查询挂载空间、受阻收折。最终完成目标为“巡检回路已恢复”。下表记录这些修订之后的最后一次统一测试；此前通过的中间版本不作为最终依据。

详细空间、路线、M0/M1差异与设计推演见[体验修订](design/l01-r1-design.md)；角色原型和主线兼容性见[栈雀](design/zanque.md)。

## 运行和操作

仓库根目录使用Node及npm；引擎精确SHA仍为 `da8ea1cf098ad99ccc89451d34bf4e272cdc15aa`。工程准备仅同步所需原生运行文件，不执行完整编辑器构建、不生成ZIP。

```bash
npm ci
npm run dev
```

浏览器打开 `http://127.0.0.1:4173`，启动播放器并点击画面。WASD移动、鼠标观察、空格跳跃、E交互；手轮需按住E。Esc暂停，R回本关入口，V语音开关，B字幕开关。语音素材状态在暂停菜单展示。测试入口直接携带栈雀，不代表S01首次获得过程已经制作。

```bash
npm run check
npm run test:unit
npm run test:browser
npm run voices:check
```

### 性能样本

最终生命周期测试里的两个短样本约13.10和14.33帧/秒，分别在入口和两次通关/三次重试后采集。它们只反映同一测试过程中的短时情况，受云端软件渲染与运行负载影响，不能据此宣称新增内容没有成本。

另以旧M1提交 `59ea3545de7a72c640e4730431a1d877f9a37725` 与最终R1做了[同环境对比](evidence/m1-r1/performance.json)。顺序为旧版→R1→R1→旧版，每次只开一个浏览器；1280×800、同一固定引擎、2秒预热、6秒采样，每版本每位置两份样本。A1采用近似相同观察位，用真实键鼠抵达，定位容差0.20米，不强改玩家/相机坐标；实际视角并非完全重合，旧版/R1原生渲染门视图数为3/4。因此它是新版整场景的近似位置比较，不能隔离某个模块的纯成本。

| 位置/指标 | 旧M1均值 | 当前R1均值 | 结论 |
| --- | --- | --- | --- |
| 入口实际frameCount/墙钟采样 | 16.30帧/秒 | 13.85帧/秒 | 约下降15.01% |
| 入口原生frame耗时 | 6.51ms | 10.55ms | 约增加62.05% |
| 入口原生render耗时 | 3.22ms | 5.23ms | 额外几何/游戏更新有可测成本 |
| A1门视实际frameCount/墙钟采样 | 5.59帧/秒 | 5.02帧/秒 | 约下降10.25% |
| A1门视原生frame耗时 | 23.44ms | 20.72ms | 短样本阶段耗时更低，不能据此反推实际帧率提高 |
| A1门视原生render耗时 | 9.30ms | 9.33ms | 此指标相近，实际软件帧率仍较低 |

四次采样无pageerror。入口mesh计数从98增至149，物理body从63增至74；本样本比较的是整轮体验修订，不能单独把差值归因于栈雀或语音。原生frame/render指标包括模拟和渲染提交，不等于GPU完成时间；墙钟帧率与它不能简单取倒数互换。

**本轮已经观察到性能开销，不能称为“性能无下降”或目标设备性能验收通过。** SwiftShader软件渲染的绝对帧率不代表用户Windows GPU，但相对下降仍需公开。下一次真人试玩应同时记录Windows浏览器/GPU、入口及近折口帧率、转向和音画舒适度，再判断是否需要在本关继续优化；没有擅自扩大到引擎重构或以降低真实门能力掩盖开销。

## 人工试玩重点与停止点

新版还需要用户判断：目标是否清楚，手轮按住是否自然，探索支路是否有价值，穿门后是否认出同一空间，机械回路是否可读，栈雀是否有陪伴感、是否遮挡或干扰思考。Windows生成真实配音后，还需检查角色声音区别、音量、字幕结束时机和台词是否喧宾夺主。

本轮提交并推送任务分支后停止，等待用户试玩新版反馈。不自动合并main，不进入下一关、正式美术或整章叙事制作。
